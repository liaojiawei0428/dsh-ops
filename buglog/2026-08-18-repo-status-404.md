16:27 起所有通过 restart-dsh-web.ps1 / start-dsh-web.ps1 / update-dsh.ps1 的服务重启都静默失效：闸门日志停在 validate-plugins 输出后，服务器进程从未被杀（实际监听进程一直是 14:32 的旧 pid 30320），新代码（repo-status 路由、bug-log 跨 turn 修复、slug 参数）从未加载——用户看到"版本检查失败"（旧进程无该路由，404）。定位过程：直接请求 /api/dsh/repo-status 得 404；对比重启日志确认 kill 未发生；最小化实验排除普通管道/spawnSync/import 单点问题；最终发现 validate-plugins.mjs 成功路径末尾缺 process.exit(0)，依赖事件循环自然清空——但 import 的 dsh-tools 核心库及新版本 balance 插件（顶层 import node:child_process 等）留下活跃句柄（定时器/监听器），事件循环不空，进程永不退出；调用它的重启脚本用管道消费输出，永远等不到 EOF，卡死在该行。修复：成功路径末尾加 process.exit(0)（失败路径本就有），验证管道形式 220ms 秒退 exit 0。教训：CLI 脚本必须显式退出，不依赖事件循环清空；闸门在重启前拦截了 balance 重复声明等错误，但自身挂起反而阻塞了正常重启。
